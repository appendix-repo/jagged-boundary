# The Jagged Boundary: replication repository

This repository is the research artifact that accompanies the Stage 1 proposal "The Jagged Boundary," submitted to the Organization Science Special Issue *AI-Enabled Frontiers in Organizational Science*. It contains the instrument, the analysis code, the response schema, the agent instruction sets and the complete records of every run reported in the technical appendix, together with scripts that regenerate every number the appendix and the proposal report. Section numbers below refer to the technical appendix, which is included as `docs/JAGGED_TECHNICAL_APPENDIX.md`.

The repository is anonymized for review. It names no author or institution.

**No human participant has taken part in anything in this repository.** The interviews in `runs/` are runs in which separate Claude instances stand in for participants, and each is labelled as such. The increment ratings were made by Claude instances acting as raters. The analysis demonstration uses synthetic respondents generated by `pipeline/simulate.py`. Appendix Section 12 states how each part was produced.

## Quick start

```
pip install -r requirements.txt
python3 replicate.py            # regenerates everything and compares it with the stored outputs, about 3 minutes
python3 replicate.py --fast     # the same without the two slow steps, about 10 seconds
```

`replicate.py` runs every step listed in the next section, compares each step's output with the stored file (ignoring only the reported run time) and compares each generated file byte for byte with the committed version. It prints `RESULT: PASS` only if every step reproduces. The same command runs on every push through `.github/workflows/replicate.yml`.

The code needs Python 3 with NumPy, SciPy and jsonschema. The stored outputs were produced with Python 3.13, NumPy 2.5.3, SciPy 1.18.1 and jsonschema 4.26.0 (pinned in `requirements.txt`). Every random draw is seeded, so the outputs are deterministic for these versions. No step calls an AI model, and no step needs a network connection.

## What cannot be rerun by a script

The stand-in interviews, the audits and the increment ratings were produced by language-model instances, and a model gives different text each time it is run. What can be checked is the record and every number derived from it. `runs/prompts/` holds every prompt exactly as given, `runs/transcripts/` the transcripts (cleaned `S*.md` and uncut `S*_raw.md`), `runs/records/` the interviewers' records, `runs/audits/` the Auditor prompts and audits, and `runs/raters/` the rater prompts and ratings. All runs used model `claude-opus-5-5`, one separate instance per participant, interviewer, auditor and rater. A reader who wants to repeat a run can give the same prompt to a model instance; the result will differ in wording, and Check 05 shows how the reported tables were computed from the records. The auditor prompts contain the file path of the transcript in the working folder where the runs were made; it is left as given.

## Notes for reviewers

- **Participant turns.** The interviewers' own records give 11 and 12 participant turns for S1 and S2. The transcripts contain 10 and 11, which is what appendix Section 4.2 reports. Check 05 counts from the transcripts and prints both numbers.
- **Power labels.** In the output of Check 03, "retest 40%" means a retest of 40% of all participants, of whom only those in orders F and R (half) can be compared, which is 0.2N comparable retests. Appendix Section 8.4 calls this row "retest from F and R only (0.2N people)". Check 07 confirms the two match.
- **Check 08 and Check 03.** Check 08's within-person retest power on the acceptance count (0.90 and 0.97) uses the same synthetic populations as Check 03 and matches it. Its between-orders figures use those populations too, and so differ slightly from Check 03's between-orders row, which uses different seeds.
- **Stand-in traversals and the schema.** The stand-in interviews used instrument v0.1 (32 items). The v0.2 schema requires 37 responses, so Check 06 validates synthetic v0.2 traversals and the four audits, not the stand-in traversals.
